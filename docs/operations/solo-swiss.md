# Local solo Swiss tournaments

Choose a completed solo draft on `/play`, then **Play Swiss rounds vs AI opponents**. `/pools/:poolId/play/swiss` prepares `/runs/:runId`, which retains an owner-bound request ID and frozen eight-seat roster. Choose BO1 or BO3 and an AI style before preparation. Existing Swiss events without `matchBestOf` remain BO3; practice and elimination keep their formats.

All eight players play three Swiss rounds, including after a loss. BO1 requires one win; BO3 requires two. Drawn games are replayed. Pairings advance only after all current matches have winners. AI-vs-AI games become eligible when the corresponding human game is requested, so they run while the human plays. Once the human match is decided, remaining AI games are released; rounds without a human pairing run normally. Preparation and sideboarding alone do not start AI games. The background worker picks up eligible games on its four-second tick. AI-vs-AI games use the same server runtime and archived results as human games, never synthetic winners. Names, canonical deck-aware SWUAPI archetypes, match records, game scores, replays, and opponent-win-percentage standings are shown on the tournament page. Archetype lookup failure falls back to local card data and does not block results.

Live human games return to the Swiss page when they end. Replays/observers never auto-return. BO3 next-game actions use the human sideboarding flow and immutable per-game deck snapshots; AI decks remain unchanged. BO1 does not force sideboarding between rounds. The existing beta/AI environment gates apply. No production rollout is included.

Validation: a local BO1 event completed all 12 matches across three rounds. All nine AI-vs-AI games ended under engine rules; the human test games were deliberately conceded. Final standings retained all eight players. Focused progression tests cover BO1/BO3, draws, human seat zero, no repeated Swiss pairings, elimination compatibility, and canonical archetypes. Browser checks cover both match lengths, names/records/archetypes, mobile containment, final standings, and live-only automatic return. Sideboarding's separate database/browser tests cover human deck edits.

When changing the imported worker/progression code in development, restart the custom Next server: hot reload updates route handlers but does not reload `server.ts`'s background worker imports. Runtime/gateway health alone does not validate this worker.
