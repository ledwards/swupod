# Icons 2027 Edition (IC27)

> **LLM INSTRUCTION**: Keep this document up to date whenever IC27 pack generation logic, belt assignments, rarity weights, or the Chaos-only gate change.

## Overview

| Property | Value |
|----------|-------|
| Set Code | IC27 (swuapi) |
| Set Number | none — non-core product (`setNumber: 9` in config is the press era only) |
| Set Name | Icons 2027 Edition |
| Formats | **Chaos Sealed and Chaos Draft only** |
| Pack | **9 cards**, no base slot (`packRules.packLayout: 'icons9'`) |
| Color | `#B8860B` |

Icons is not a numbered core set. It rotates nothing and is never drafted or
sealed on its own in PTP.

## How "Chaos only" is enforced

- **Registry.** `IC27_CONFIG` lives in `CHAOS_ONLY_SET_CONFIGS`, never
  `SET_CONFIGS`. Draft/Sealed/Rotisserie landings, rotation (`latest.ts`), the
  Play card pool, `/api/entry`, imports and stats all iterate `SET_CONFIGS`, so
  none of them see Icons. `getSetConfig('IC27')` still resolves it so packs print.
- **Server.** `getUnavailableSetReason` rejects chaos-only codes unless the
  caller passes `{ allowChaosOnly: true }`. Only Chaos Draft (`/api/draft` with
  `draftMode: 'chaos'`) does; Chaos Sealed never calls that gate. Pack Wars,
  Pack Blitz and Rotisserie reject `isChaosOnlySet` codes explicitly.
- **Client.** `fetchSets` lists IC27 only with `includeChaosOnly: true`, which
  only the Chaos Sealed / Chaos Draft pickers pass.

## Pack (9 cards — `generateIconsBoosterPack`)

FFG's pouch reads "9-CARD BOOSTER PACK". Slot order and rates come from real
boxes (see "Real box openings"), rounded to printable sheet counts.

| Slot | Contents |
|---|---|
| 0-2 | Common x3 (Belt A, Belt A, Belt B) |
| 3 | Leader 1 in 4, otherwise a Common (`IconsLeaderSlotBelt`: 12 leaders per 48-pack strip) |
| 4 | Hyperspace Common (guaranteed) |
| 5 | Uncommon |
| 6 | Uncommon — upgrades 9 per box on the Icons sheet (`uc3HsOutcomeCounts`): 6.67 HS UC / 1.33 HS R / 1 HS L — uncommon or better only, never an HS Common or Special |
| 7 | Hyperspace Foil — sheet copies C40/U5/R2/S1/L1 ≈ 20.2 C / 2.5 U / 1 R / 0.2 L / 0.07 S per box |
| 8 | Rare or Legendary (never upgrades), legendary 1 in 5 |

- **No base slot.** Icons bases (and the Vader/Leia leaders, C-3PO, R2-D2,
  Death Trooper, HK-87) have no Hyperspace printings — they read as Starter
  Set cards, so packs never contain them.
- Leaders in slot 3 are the 6 Common leaders; HS leader and Showcase upgrades
  use the HMW-era rates.
- The HS leader plan is reused from the Block B press (`setNumber: 9`). No
  prestige.
- Commons auto-assign to Block B belts A/B (`commonBeltAssignments.ts`).

Sim per 24-pack box: 6 leaders (1 HS), 4.8 R/L-slot legendaries, UC2
upgrades 9 (6.67 UC / 1.33 R / 1 L).

## Drafting Icons

Icons has no leader slot, so an Icons pack's leader is **not** pulled into the
leader draft — it stays in the pack and is drafted like any card
(`hasLeaderSlot`). The leader draft runs one round per pack whose set has a
leader slot (`draftState.leaderRounds`); an all-Icons chaos draft has none and
opens picking straight on pack 1. Players can end with different leader counts.

Bots undervalue a pack leader: once a bot has a leader, a pack leader scores
at half (`PACK_LEADER_VALUE`, `src/bots/behaviors/packLeaderValue.ts`); a bot
with no leader values it fully. In an all-Icons 8-seat draft there are ~6
leaders for 8 seats, so ~1 in 3 seats ends without one.

## Slot-type tracking

Card-generation tracking labels Icons cards with `ICONS_PACK_SLOT_TYPES`
(`src/utils/packSlotTypes.ts`) via `slotTypeForPackCard`, so no Icons card is
recorded as a base. Slot 3 is recorded as `leader` when it printed a leader and
`common` otherwise.

Packs printed before the foil moved ahead of the R/L were labelled at write
time in the old order (7 R/L, 8 foil), so their labels already match their
cards; migration 122's Icons branch only rewrites the older leader/base-shaped
rows, which were also printed R/L-then-foil.

## Slot tracking for other layouts

- LAW+ packs (sets whose config sets `packRules.foilSlotIsHyperspaceFoil`) are now
  tracked with `LAW_PLUS_PACK_SLOT_TYPES` (foil at 11, uncommons at 12-14, R/L at 15).
- Rows written before these fixes were relabelled by migration 122
  (`migrations/122_relabel_set7plus_and_icons_slot_types.sql`), which also marks
  the stored QA stats for these sets stale. It only touches packs whose labels
  have the old shape, so it is safe to re-run. Rows with no `pack_index` and the
  16-card Icons packs printed before Icons became a 9-card pack are left as they
  were. `scripts/test-slot-relabel-migration.ts` checks it on a scratch database.
- Carbonite (`-CB`) packs carry their own `carbonite_*` labels, one map per
  Carbonite layout (pre-LAW, LAW, ASH), and the QA stats leave them out since they
  measure standard boosters. `migrations/123_relabel_carbonite_slot_types.sql`
  relabelled the older rows; `scripts/test-carbonite-slot-relabel-migration.ts`
  checks it on a scratch database.
