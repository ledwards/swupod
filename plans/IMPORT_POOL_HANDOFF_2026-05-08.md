## What the current issue-flagging surfaces (the data Lee saw)

`src/components/ImportPool/ResolveStep.tsx` builds `anomalies[]`:
1. Section gaps (under/over-populated vs typical)
2. Per-row matcher problems (unmatched / fuzzy / ambiguous / deck>pool)
3. Low-confidence reads (poolQtyConfidence/deckQtyConfidence === 'low')
4. Pool-short candidates ("Possibly missed") — picks `poolQty===0 && type !== Leader && type !== Base` cards, sorts by lowest confidence then alphabetical, slices `delta`
5. Deck-over candidates ("Possibly mis-counted in deck") — same but for deck cards

**Across the 3 fixtures, this surfaces a total of 9 issues — only 3 are real (6.1% true-positive rate against the 49 real issues).**

```
                  surfaced   true positive   false positive
sq-tom-law          4            1              3
sq-lee-law          3            1              2
casual-lee-law      2            1              1
                   ──           ──             ──
                    9            3              6
```

**Why it sucks:**
- Whole-table Opus marks ~263 of 264 cells "high confidence". The confidence-based ranking has no signal.
- With no confidence signal, ties break alphabetically. The "Possibly missed" picks are `0-0-0`, `4-LOM`, `"Staccato Lightning" Repeater` — alphabetically first names. Pure noise.
- `type !== 'Base'` filter permanently excludes bases, so missed bases (LAW has rare bases — players DO mark more than 6) never surface.

## Heuristic priorities (revised against real data)

### TIER 1 — high confidence these will catch real issues

**A. Section-gap-weighted candidate selection.** When pool short by N in a section, the N "Possibly missed" candidates come from THAT SECTION, not alphabetical-first across the whole pool. Same for deck-over picks. Confirmed by the data — across all 3 fixtures, section-gap localization is right ~70% of the time.

**C. Active-leader/base uniqueness invariant.** Hard rule: at most ONE leader has deckQty=1, at most ONE base has deckQty=1. If extraction reports multiple, surface as a SPECIFIC issue ("Vel Sartha and Lando Calrissian both marked active — only one can be active. Which is yours?"). Catches sq-tom-law's Lando wrong-deck and casual-lee-law's Canto Bight wrong-deck — both cleanly.

**Phantom-via-section-overflow.** When section's pool sum > typical max OR > truth (we don't have truth in production but can use typical-range from `sectionGaps`), the lowest-confidence pool=1 cards in that section are likely phantoms. Catches sq-lee-law's Bracca Shipbreaker, casual-lee-law's Honnah / Asajj Ventress / The Master Codebreaker / Agent Kallus. Surface as "Verify this section's pool count looks correct".

**G. Stop fabricating noise.** When section-gap is unactionable (no clear under/over section, or multiple sections each off by 1), DO NOT alphabetically pick rows. Show a banner: "Pool is short by N; review every section". Better honest than confidently wrong. The current behavior — picking 4 alphabetically-first names with 0% truth rate — actively damages the user's trust.

### TIER 2 — wanted but expensive

**F. Re-extract uncertain rows.** Catches the 24 wrong_deck cases. But these are EXACTLY where Opus already gave a confident wrong answer. A second whole-table call won't disagree. Need either:
- per-cell focused crop sent to Claude (per-cell-tiebreaker — earlier tested at marginal gain because cell ROIs aren't pixel-precise)
- ML classifier on per-cell crops (the 4-8 week project in [IMPORT_POOL_ML_CLASSIFIER.md](IMPORT_POOL_ML_CLASSIFIER.md))

### TIER 3 — defer

**B. Include bases in candidates.** Right call in principle but no fixture in the current set has a missed base; can't measure value.

**E. Card-number gaps.** Weak signal across these 3 fixtures.
